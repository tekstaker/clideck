  <name>Task 2: External-terminal manual smoke — ack, heartbeat, watchdog, SIGTERM, recovery</name>
  <what-built>
    An observable, hard-timed shutdown for clideck: a signal-named ack banner,
    per-step timing lines, a 3s heartbeat naming the current step + elapsed
    seconds, a 10s watchdog that force-exits a hang, and a `[clideck] goodbye.`
    success line. Wired in server.js via the new shutdown.js factory; the
    sessions.shutdown PTY-kill loop now yields between kills so the heartbeat
    and watchdog actually fire.
  </what-built>
  <how-to-verify>
    Do ALL of this from an EXTERNAL terminal (PowerShell / Windows Terminal),
    NEVER from inside the host clideck session (recursive footgun —
    memory/feedback_clideck-meta-work.md). Use a throwaway port + isolated data
    dir (memory/feedback_verify-clideck-ui-altport-playwright.md).

    1. AC 1 (ack ≤50ms) + AC 6 (goodbye), 0 PTYs:
       In PowerShell: `$env:PORT=4099; $env:DATA_DIR="$env:TEMP\clideck-13smoke"; node bin/clideck.js`
       Wait for the booted banner. Press Ctrl+C. CONFIRM:
       - `[clideck] Ctrl+C received — shutting down…` appears effectively instantly (on its own line, separated from the shell `^C`).
       - Three step lines print: `flushing plugins… done (Xms)`, `stopping activity… done (Xms)`, `persisting sessions…` (with `killing 0 PTYs… done` nested) `done (Xms)`.
       - Final line `[clideck] goodbye.` then the prompt returns. Exit was clean.

    2. AC 1/2 with 1 and 4 PTYs:
       Re-boot the same way. Open the UI at http://127.0.0.1:4099, create 1 terminal session, then press Ctrl+C in the launching terminal. CONFIRM the `killing 1 PTYs… done (Xms)` line. Repeat with 4 sessions; CONFIRM `killing 4 PTYs… done`.

    3. AC 4 (heartbeat) + AC 5 (watchdog), with an INJECTED slow step:
       Temporarily add an artificial delay inside one step to force a hang —
       e.g. set the env the executor wired for this, OR (if none) edit shutdown.js
       locally to make `flushing plugins` await a 12-second sleep, run, Ctrl+C,
       and CONFIRM:
       - At ~+3s: `[clideck] still shutting down… (current step: flushing plugins, elapsed: 3s)`.
       - At ~+6s and ~+9s: further heartbeats with rising elapsed.
       - At ~+10s: `[clideck] shutdown took too long — forcing exit` and the process exits (the 12s sleep never completes — the watchdog won). REVERT the injected delay afterwards.

    4. AC 7 (SIGTERM parity):
       Re-boot. Note the pid from the boot banner. In a SECOND terminal run
       `taskkill /PID <pid>` (WITHOUT `/F`). CONFIRM the launching terminal shows
       `[clideck] SIGTERM received — shutting down…` then the same step lines and
       `[clideck] goodbye.`.

    5. AC 9 (recover via Ctrl+C alone):
       During the step-3 hang scenario, CONFIRM that Ctrl+C alone got you back to
       a prompt within the 10s watchdog window — you never had to close the
       terminal window.

    Clean up the throwaway data dir (`$env:TEMP\clideck-13smoke`) when done.
  </how-to-verify>
