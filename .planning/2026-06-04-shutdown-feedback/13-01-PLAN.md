<objective>
Make `sessions.shutdown(cfg)` async and yield to the event loop between each PTY
kill, and add a PTY-kill-count log line. This is the foundation that lets the
heartbeat and watchdog (Plan 02) actually fire during the worst-case hang — the
synchronous per-PTY `pty.kill()` loop on Windows ConPTY (per 13-CONTEXT.md
finding "the per-PTY kill loop is the real worst-case").

Purpose: D-01 (async + setImmediate yields) and D-03 (PTY-count log). Without
the yield, the kill loop blocks the event loop and the heartbeat/watchdog never
tick — defeating the entire phase.
Output: Modified `sessions.js`; updated `tests/session-pause.test.js`.
</objective>

From sessions.js:
```javascript
function shutdown(cfg) {
  clearInterval(autoSaveInterval);
  saveSessions(cfg);
  for (const [, s] of sessions) {
    try { s.pty.kill(); } catch {}
  }
}
// exported at sessions.js:751 as `shutdown` (named export on module.exports)
// `sessions` is a module-scope Map; `sessions.size` gives the PTY count.
// `autoSaveInterval` and `saveSessions` are module-scope; keep their calls sync.
```
The only existing caller in tests is tests/session-pause.test.js:127:
`sessions.shutdown?.(CFG_WITH_RESUME); // ensure final flush`
This is a fire-and-forget call that becomes a returned Promise; it must be awaited.
