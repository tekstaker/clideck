## ws library facts (RESEARCH §1 + §7)
- verifyClient 2-arg callback: `callback(verified, code, message, headers)`. Returning verified=false aborts the upgrade with HTTP `code`; browser sees event.code=1006 (the HTTP status doesn't propagate to the close event — RFC 6455 fact).
- handleProtocols: returning the sentinel string `'clideck-device-token'` echoes it back in the Sec-WebSocket-Protocol response header. Returning false makes ws OMIT the header, causing the browser to fail the handshake (event.code=1006). Per RESEARCH §1 R-1: we MUST return the sentinel, NOT the raw token, for accepted connections.
- onConnection is wss.emit('connection', ws, req) — the second arg is the upgrade Request, currently ignored by handlers.onConnection at handlers.js:266.
