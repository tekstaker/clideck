## Existing analog — session-ask.handleHttp (session-ask.js)

## Why dependency injection (deps = { devices, pairOtp })
PATTERNS §1 row 7 calls out this is the first HTTP-handler unit test in clideck. Without DI, the
test would have to mutate the module's `require.cache` or monkey-patch globals. With DI, the test
imports the route module fresh AND supplies its own freshDevices() / freshOtp() instances. Wave 0's
`tests/pair-redeem.test.js` is written against this DI contract — see freshPair() in 16-01-PLAN.

## /pair/mint-otp auth gate (planner pin for RESEARCH §10.4 open)
RESEARCH §10.4 punted on the exact auth shape for /pair/mint-otp. Pinning now: the handler reads
header `X-Clideck-Device-Token`; looks up via `devices.findByToken(value)`; on hit, mints a 5-min
OTP and returns `{ ok: true, otp, expires_at }`; on miss or absent header, returns 401 `{ ok: false,
error: 'unauthorized' }`. This lets an already-paired client (browser) call /pair/mint-otp using
the same token it stores in localStorage — no separate session cookie needed.

This is non-trivial because the same token rides the WS subprotocol AND now a custom HTTP header.
The two surfaces share the same `devices.findByToken` lookup, so the lifetime semantics stay
identical (token revoked → both surfaces start rejecting on the next call).
