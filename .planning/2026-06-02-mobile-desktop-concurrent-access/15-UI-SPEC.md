## "Other client connected" indicator — exact contract

This is the only net-new visible UI artifact in Phase 12. CONTEXT.md D-10 leaves glyph/colour/position to "planner's call" with the constraint *must not collide with the unread dot or working indicator (Phase 5 mutex)*. This UI-SPEC locks all four below.

### Visual

| Property | Value | Rationale |
|----------|-------|-----------|
| Shape | Two thin concentric outlined circles, **6×6px overall** (`w-1.5 h-1.5`), rendered as an inline SVG | Reads as "two presences" at a glance; distinguishes from the solid `bg-blue-500` unread dot semantically |
| Color | `text-amber-400` (Tailwind) | Amber is the only warm hue in the existing palette not already claimed by accent (blue) or destructive (red). High readability against both `--color-surface` dark and light surfaces |
| Background | none (transparent — it's a stroke-only icon) | The unread dot is a *filled* solid; this one is an *outline*. The fill/stroke distinction is the primary visual differentiator |
| Animation | none — static | Mutex precedent (Phase 5) avoids visual fights; an animated badge would re-introduce the noise Phase 5 deliberately removed |
| Hover/focus | no special state — it's display-only, not interactive | Following the existing `.unread-dot` precedent (also non-interactive) |

### Position on the session row

The row's existing structure (from `terminals.js:507–526`):

```
┌─────────────────────────────────────────────────────────┐
│ [icon]   name                              time         │
│         status·  preview…           [•unread]  [⋯ menu] │
└─────────────────────────────────────────────────────────┘
   8×8     ← flex-1 column with two stacked rows →    interactive
```

The new indicator goes in a **NEW slot to the LEFT of `.session-time`** on the **top row** (the row currently containing `name` + `session-time`). Concretely, append it as a sibling of `<span class="session-time">` inside `<div class="flex items-baseline gap-2">` at `terminals.js:514`, ordered as:

```
[name (truncate)]  [other-client indicator]  [time]
```

This placement:
- Does NOT collide with the unread-dot slot (different row).
- Does NOT collide with the working-indicator slot (different row).
- Is visible whether the row is hovered, active, or default (other badges only appear conditionally).
- Survives the existing `.name` truncation because the indicator is `flex-shrink-0`.

### DOM contract (planner/executor lock)

The exact markup to add at the marked insertion point in `terminals.js` row template:

```html
<span class="other-client-indicator hidden flex-shrink-0 text-amber-400"
      title="Another client is connected"
      aria-label="Another client is connected">
  <svg width="10" height="10" viewBox="0 0 16 16" fill="none" stroke="currentColor" stroke-width="1.5" aria-hidden="true">
    <circle cx="6" cy="8" r="3.5"/>
    <circle cx="10" cy="8" r="3.5"/>
  </svg>
</span>
```

- Default state: `.hidden` (Tailwind).
- Visible state: client-side WS `clients.count` handler removes `.hidden` on every session row when `count > 1`, re-adds it when `count <= 1`. Per D-10/D-11 this is a single `state.otherClientsConnected` flag driving a class toggle on all `.session-row` and `.resumable-row` elements — no per-session bookkeeping.
- The two-overlapping-circles glyph encodes "two presences" semantically (vs. the single solid unread dot). The 10×10 SVG inside a 10×10 span keeps tap-target irrelevance (it's display-only, no pointer events) but visually balances the 12×12 timestamps and 18×18 menu chevron already on the row.

### Accessibility

| Surface | Contract |
|---------|----------|
| `title` attribute | `"Another client is connected"` |
| `aria-label` | `"Another client is connected"` (matches title; screen readers announce on focus / virtual cursor) |
| `aria-hidden` on inner SVG | `"true"` — the wrapping `<span>` carries the label, the SVG is decorative |
| Color-only signaling | NOT solely relied on — the glyph SHAPE (two circles) differs from the unread dot's single circle, so users with deuteranopia / protanopia distinguish them without relying on amber-vs-blue |
| Reduced motion | n/a — indicator is static |

### Resumable-rows ("Previous Sessions")

Apply the same indicator to `.resumable-row` entries with the same toggle rule. CONTEXT.md D-08 confirms the count is server-wide, so EVERY session row + every resumable row gets the indicator when `count > 1`. The DOM insertion point in the resumable row template follows the same shape — top row, left of timestamp.

### Layout at 375×667 (iPhone-ish) — must match

| Surface | Behaviour |
|---------|-----------|

Toggle via `#mobile-nav-toggle` (40×40px tap target at `top: 12px; left: 12px` with safe-area-inset offset — already in place at `index.html:93–106`). ### Terminal pane overflow — LOCKED decision

Per SPEC R6 acceptance: *"The terminal itself letterboxes or scrolls horizontally to show the locked PTY width (per Requirement 2) without reshaping the PTY."*

**Decision: horizontal scroll, NOT letterbox.** Rationale: xterm.js already lays its grid out as a wide DOM area inside its container; adding `overflow-x: auto` on the terminal wrapper is a single CSS rule per CONTEXT.md D-16. Letterboxing would require a transform-scale path which complicates touch hit-testing, font rendering crispness, and the Phase 9 `display-sizing.js` re-fit math. Lean wins.

Specific CSS contract (planner translates into the appropriate selector — likely `.term-wrap` from `terminals.js:538`, but planner verifies):

```css
@media (max-width: 960px) {
  .term-wrap {
    overflow-x: auto;
    /* xterm's own .xterm element already has its width set by the locked PTY */
    /* Ensure the horizontal scrollbar is touch-friendly */
    -webkit-overflow-scrolling: touch;
  }
}
```

Add this to the existing 960px block in `index.html`. Do NOT introduce a separate stylesheet.

## Cross-mode (dark / light) verification contract

The app supports both modes via the `.light` class on `<html>`. The new indicator must render correctly in both:

| Mode | Indicator glyph color | Verified against background |
|------|----------------------|-----------------------------|
| Dark (default) | `text-amber-400` ≈ `#FBBF24` on `bg-slate-900` (`--color-surface` dark) — contrast ratio ~9.8:1 | passes WCAG AA non-text contrast (≥ 3:1) |
| Light | `text-amber-400` on light `--color-surface` (~`#f6f5f5`) — contrast ratio ~2.1:1 | **borderline for non-text contrast** — see contingency |

**Contingency for light mode:** if light-mode contrast verification fails at the visual check (gsd-ui-checker dimension 3), swap to `text-amber-500` (≈ `#F59E0B`, ~3.2:1 on light surface) under the `.light` selector. This is a one-line CSS escape — the planner picks the cleanest expression (Tailwind responsive variant vs. `:where(.light) .other-client-indicator { color: ... }`). The shape (two-circle outline) carries the meaning even if hue contrast is marginal — color is not the sole signal.
